Troubleshooting

Almost everything the mod does shows up in the game log, so most problems are one search away.

On this page

  2. No log lines at all

  4. The buffer shows 0h
  5. "Switched off for this session"
  6. Beavers still cross the map
  7. Everyone eats at once

  9. Stutter in a big colony
  10. Co-op drifts apart

The mod doesn't appear in the mod manager

Likely cause
The folder is in the wrong place or nested one level too deep, so the game can't find manifest.json.
Fix
  1. Close Timberborn.
  2. Open Documents\Timberborn\Mods and check that this file exists: HungryPathing\version-1.1\manifest.json.
  3. If it is at HungryPathing\HungryPathing\version-1.1\manifest.json instead, move the inner folder up a level.
  4. Make sure you extracted the whole zip. Scripts\HungryPathing.dll and Needs\ must sit next to manifest.json.
  5. Start the game again. See the install steps for the exact layout.

The mod is listed but there are no [HungryPathing] lines in the log

Likely cause
The mod is disabled in the mod manager, or Harmony is missing or disabled, in which case the game could not load the mod's code and logs an error mentioning HarmonyLib instead.
Fix
  1. In the mod manager, enable Harmony first, then Hungry Pathing, and restart.
  2. Search the log for HarmonyLib. If an error names it, install Harmony from the Steam Workshop.

The log says "A hook could not be installed; the game runs unmodified"

Likely cause
A game update moved one of the five methods the mod attaches to. The mod then installs none of them and does nothing for the session, on purpose.
Fix
Check the releases page for a build that names your game version. If there is none, report it with the warning line, which says which hook failed. Your colony is unaffected in the meantime.

"Needs in this game" shows a buffer of 0h

Likely cause
The two blueprint patches were not applied. Either the Needs folder is missing from version-1.1, or another mod that also edits the Hunger or Thirst blueprint loads after this one and sets the field back to zero.
Fix
  1. Check that version-1.1\Needs\Need.Beaver.Hunger.blueprint.json and the Thirst file exist.
  2. If another mod edits those blueprints, change the mods' order in the mod manager so this one loads later, or set WarningHours = 3 in HungryPathing.cfg, which overrides the blueprint value.
With a buffer of 0h the just-in-time rule waits until the last moment and the pre-fuel rule triggers less, but nothing breaks.

The log says "Switched off for this session after an error"

Likely cause
Something in the mod's own code threw. The mod logs the stack trace once and disables itself so the game carries on as if it were not installed.
Fix
Please report it with the whole warning, including the lines after it. Restarting the game re-enables the mod; if the warning comes back at the same point, set Enabled = false until a fix is out.

Beavers still walk across the map to eat

Likely cause
The nearby storage is not usable for that beaver at that moment, or the trip is not one the mod controls.
Check
  1. Is the storage in the beaver's district? Beavers only see storages registered with their own district center.
  2. Does it hold food or water right now? Units already reserved by beavers on their way count as gone, so a small warehouse can be empty for the next arrival.
  3. Is the beaver off duty? Evenings run the game's own behavior on purpose, and that is where variety-seeking happens.
  4. Is it a penalty-state trip during work? Those follow the mod only while RedirectCriticalTrips = true, and not for RetryHours after a redirect in which every storage the mod measured failed to start a trip. Each such failure counts in the daily line's failed launches.
  5. Read the daily Day N: trips started by rule line. If every count is zero, the planner never fires: check the buffer and that Enabled = true. Set Diagnostics = true to see each trip and the walking time it measured.

Everyone heads for food at the start of the shift

What is happening
The pre-fuel rule: a beaver that would not last the whole shift plus the buffer, and has food within half an hour, tops off before starting work. The first morning after installing, many beavers qualify at once because the game never topped them off; after a day it settles into the ones the evening missed.
If you want less of it
Lower PreFuelNearFoodHours so only beavers right next to food do it, or set PreFuel = false and keep the just-in-time rule. Food consumption per day is the same either way; only the timing moves.

A builder keeps letting go of the same site

What should happen
A builder lets a site go at most once per half hour of game time, tops off, and then takes whatever site the game hands it next. Seeing the same builder drop a site repeatedly without eating in between means the food it counted on was gone by the time it got there.
Fix
Set BuilderJobCheck = false for now and report it with Diagnostics = true lines around the event. The other rules keep working.

Stutter in a big colony

What to look at
The daily line ends with the number of path queries the mod made. A few thousand per day for a few hundred beavers is normal and cheap; tens of thousands is not.
Fix
Lower CandidateLimit (path queries per check), raise RetryHours (time between checks), or lower JustInTimeLeadHours (how early walks start being measured). All three are simulation settings, so co-op peers must change them together.

A co-op game drifts apart after installing the mod

Likely cause
The players run different versions of the mod or different settings files. Both change what beavers decide.
Fix
Compare the Simulation settings: line each player's log prints at startup, and the version in the loading. line. Make them identical, then start from a fresh sync.

Finding the game log

Timberborn writes a log every time it runs. On Windows it is here:

%USERPROFILE%\AppData\LocalLow\Mechanistry\Timberborn\Player.log

Paste that into the File Explorer address bar to open it. Player-prev.log next to it is the previous session, which is useful if the game crashed. Search the file for [HungryPathing]. You'll see:

  • [HungryPathing] <version> loading., the settings line, Hooks installed (5/5). and Active. when the mod started normally.
  • Needs in this game: ... once a colony is running, with the buffer per need.
  • Day N: trips started by rule: ... once per in-game day.
  • Switched off for this session ... followed by a stack trace, if something went wrong.

No [HungryPathing] lines at all means the game never loaded the mod, so go back to the first fix.

Reporting a problem

Open an issue on GitHub and include as much of this as you can:

  • The mod version (from the mod manager, or the loading. log line) and your Timberborn version.
  • Whether you use BeaverBuddies, and which other mods are enabled.
  • What you did, what you expected, and what happened instead.
  • Every [HungryPathing] line from Player.log, especially the settings line, the Needs in this game line, the daily summaries and any warning with the lines after it.
